## 一、产品定位

个人开发者指挥中心：一个页面 → N 个 agent 窗口并排 → 专注交互。传统 IDE 的目录树、代码面板退居辅助位。

### 交互模式

- **Phase 1**：N 宫格多 agent 独立工作——每开一个格子启动一个 oh-my-pi，各自绑定不同工作区/项目目录，互不干涉。用户在各格子间来回交互，避免切换页面
- **Phase 2**：叠加协作——主控 agent 可通过 `task` 工具拆任务 spawn 子 agent，子 agent 间通过 `irc` 通信。用户可随时点进任意节点窗口直接对话

### Roadmap 演进

| 阶段 | 目标 |
|------|------|
| Phase 1 | 多 Agent 独立工作台（N 宫格 + 各自独立） |
| Phase 2 | Agent 协作（task 子代理 + irc 通信） |
| Phase 3 | 成本与预算控制 |
| Phase 4 | Electron 桌面壳 |
| Phase 5 | 团队协作平台（远期） |

## 二、技术栈

| 层 | 技术 | 用途 |
|---|------|------|
| **前端** | Vue 3 + Vite + TypeScript | SPA 框架 |

**关键设计点：**
- 左栏：工作区级联 + 树形目录，agent 绑定到工作区
- 中栏：N 宫格 ↔ 单屏切换，agent 格子内为终端风格（非聊天气泡）
- 右栏：代码查看器，可关闭
- 顶栏：全局控制，主控 agent 状态 + 添加 agent + 布局切换 + 设置

## 五、数据流与通信协议

| 层面 | 方案 | 说明 |
|------|------|------|
| Agent 运行模式 | `--mode json` | JSONL 结构化输出，Backend 解析事件类型 |
| 前端↔后端 | WebSocket（推流） + REST（管理） | WS 低延迟推 agent 输出，REST 管理操作 |
| 文件变更 | chokidar → WS → UI | 代码预览面板实时刷新 |
| Agent 间通信 | oh-my-pi 内置 `irc` 工具 | DM/广播，无需额外扩展 |
| 子 Agent | oh-my-pi 内置 `task` 工具 | 隔离 worktree + 类型化返回 |
| Token 计数 | oh-my-pi Rust BPE（进程内） + Backend 聚合 | Backend 只做累加和预算校验 |
| MCP | oh-my-pi 原生集成 | 无需 pi-mcp-adapter |
| 预算控制 | Backend 自研 | 参考 Paperclip 硬上限机制 |

## 六、oh-my-pi 能力覆盖

oh-my-pi 已内置的能力，Backend Service 无需自研：

| 能力 | oh-my-pi 方案 |
|------|--------------|
| Agent 间通信 | `irc` 工具（DM/广播） |
| 子 Agent 并行 | `task` 工具 + Swarm 扩展 |
| MCP 协议 | 原生集成 |
| 模型提供商 | 50+ 模型，含 DeepSeek/通义/Kimi/智谱/千帆 |
| Token 计数 | Rust BPE 内嵌 |
| API Key 轮换 | Round-robin + 退避 |
| 后备链 | 模型失败自动切换 |

**唯一需要自研的：预算控制器**（聚合 Token → 硬上限 → 拒绝/终止 agent）。

## 七、MVP 分阶段计划

### Phase 1：多 Agent 独立工作台
> 每开一个格子 → 启动一个独立的 oh-my-pi 进程，各自干活互不干涉。暂不实现 agent 间协作。

- [ ] oh-my-pi 进程管理（spawn/kill/stdin/stdout）
- [ ] Vue 3 三栏布局骨架
- [ ] 左侧工作区目录树（工作区 ↔ 目录绑定）
- [ ] 中间 N 宫格 Agent 终端（xterm.js + markstream-vue 渲染）
- [ ] N 宫格 / 单屏切换 + 顶部标签栏
- [ ] Agent ↔ 工作区目录绑定（每个 agent 启动时指定 cwd）
- [ ] 右侧代码预览（Monaco，可关闭）
- [ ] WebSocket 实时推流（多路复用）
- [ ] 多 agent 并行启动与生命周期管理

### Phase 2：Agent 协作
- [ ] oh-my-pi `task` 子 agent 可视化（主控拆任务 → spawn worker）
- [ ] `irc` agent 间通信日志与监控
- [ ] 树形会话视图（展示 task spawn 的父子关系）
- [ ] 文件预留冲突提示

### Phase 3：成本与预算
- [ ] Token 用量聚合与仪表盘
- [ ] 按 agent / 项目维度统计
- [ ] 预算硬上限与超限通知
- [ ] 模型切换 UI

### Phase 4：Electron 桌面壳
- [ ] 托盘图标 + 全局快捷键
- [ ] 自动启动本地 Backend
- [ ] 窗口管理
- [ ] 打包发布

### Phase 5：团队平台（远期）
- [ ] 用户认证
- [ ] 多租户工作区
- [ ] 远程 agent 池
- [ ] 协作看板

## 八、决策历史

| 决策点 | 选项 | 选择 | 理由 |
|--------|------|------|------|
| 底层引擎 | Pi Agent / Codex CLI / Claude Code | **oh-my-pi** | 树形会话 + 国产模型 + MCP + 子agent 全内置 |
| 前端框架 | React / Vue 3 / Svelte | **Vue 3** | 生态满足需求，markstream-vue 成熟 |
| UI 形态 | Electron / Web SPA / Tauri | **先纯 Web MVP，后加 Electron 壳** | 快速验证核心体验 |
| 后端架构 | 内嵌子进程 / 独立后端服务 / 内嵌 HTTP 服务 | **内嵌 HTTP/WSS 服务** | 前后端解耦，平滑升级到纯 Web |
| Agent 运行模式 | TUI / JSON 模式 | **`--mode json`** | 结构化输出，Backend 精细控制 |
| 社区扩展 | pi-messenger + pi-mcp-adapter | **不采用** | oh-my-pi 已内置等价能力 |
